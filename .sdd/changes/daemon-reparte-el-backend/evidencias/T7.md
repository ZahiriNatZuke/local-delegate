## Interfaz que consume T10

- `leer(ruta, *, version=1) -> Foto | SinTopologia`; nunca lanza.
- `foto()`: lee `config.llamaswap_config_path()` (el plan dice `config.LLAMASWAP_CONFIG`, que no existe
  como atributo; la función es la puerta real) y cachea por `(ruta, mtime_ns, tamaño)`. Cada relectura
  sube `version`. Sin variable o con el fichero inaccesible no cachea.
- `SinTopologia(motivo, detalle)`; la igualdad compara solo `motivo`. Motivos (constantes del módulo):
  `"sin LLAMASWAP_CONFIG"`, `"sin PyYAML"`, `"ilegible"`, `"matrix"`, `"dos sintaxis"` y uno añadido,
  `"no cumple load.go"` (config que llama-swap no arrancaría: miembro en dos grupos, TTL negativo,
  etc.; el `detalle` lleva los errores).
- `Foto`: `ruta`, `version`, `modelos`, `grupos` (`Grupo(swap, exclusive, persistent, miembros)`, con
  `(default)` siempre presente), `alias`; métodos `resolver(m)`, `grupo(m)`, `choca(a, b)`,
  `ttl_efectivo(m)`, `mmproj(m)` (ruta o `None`, vía `huella.flags_del_cmd`), `precargados()`,
  `residentes()` (TTL efectivo 0).
- `validar_como_load_go(datos) -> list[str]` (vacía = válida), para T11.
- `lecturas()` y `_olvidar()` para los tests.
- Lo que **no** hace: decidir que un backend remoto va sin turno (REQ-002, parte del backend). El
  módulo no conoce el backend; eso queda para T10.

## Hallazgos para otras tareas

- **Sin `globalTTL`, un modelo sin `ttl` es residente** (TTL efectivo 0): el defecto de v255 es 0.
  Tiene test propio (`test_sin_global_ttl_la_ausencia_vale_cero_y_es_residente`). Importa para el
  veredicto de REQ-029 y para `--ninguno` de REQ-030.
- **Un grupo `persistent` con `exclusive` por defecto sí desaloja a los demás al cargar** (lo protege
  de ser desalojado, no evita que desaloje). Test: `test_exclusive_contra_persistent`. Es la razón por
  la que `--fijar` (REQ-031) tiene que escribir `exclusive: false` explícito.
- Con la config de hoy los cinco modelos chocan entre sí (un solo grupo con `swap`); con la del
  2026-10-06, el 4B no choca con el 26B y no hay residente (TTL 600).

## Corrección tras la revisión

### Lo que se reprodujo

Script en el scratchpad que llama a `topologia.leer` con YAML válido de forma rara. Antes del arreglo:

| Caso | Resultado |
|---|---|
| `routing: hola` | lanza `AttributeError: 'str' object has no attribute 'get'` |
| `routing: {router: hola}` | lanza `AttributeError` |
| `routing: {router: {settings: 5}}` | lanza `AttributeError` |
| `groups: {g: [a]}` | lanza `AttributeError: 'list' ...` |
| `hooks: [1]` | lanza `AttributeError: 'list' ...` |
| `hooks: {on_startup: [1]}` | lanza `AttributeError` |
| `members: 3` | lanza `TypeError: 'int' object is not iterable` |
| `aliases: 7` | lanza `TypeError` |
| `members: a` (cadena) | **no lanza pero miente**: Python recorre la cadena y da un grupo con el miembro `a` (con `ab` saldrían `a` y `b`); Go no convierte una cadena a `[]string` |

Y `foto()` guardaba en caché el `SinTopologia("ilegible")` de un `OSError` al abrir, hasta el siguiente cambio de `mtime`.

### Lo que se cambió (`src/local_delegate/topologia.py`)

- `_errores_de_forma(datos)`: comprueba los tipos que el `Config` de v255 tiene que poder deserializar (`models` y cada modelo mapa; `aliases` lista de textos; `cmd` texto; `routing`, `routing.router`, `routing.router.settings` mapas; `use` texto; `groups` en los dos sitios mapa de mapas; `members` lista de textos; `hooks`, `hooks.on_startup` mapas; `preload` lista de textos). La llaman `validar_como_load_go` (devuelve esos errores y no sigue) y la lectura, antes de `_sintaxis`. Motivo: `"no cumple load.go"`, con el error en `detalle`.
- `leer` delega en `_leer(ruta, version) -> (resultado, pasajero)`; `pasajero` es `True` solo para un `OSError` al abrir o leer. `foto()` no cachea ni sube `version` cuando es pasajero. Un YAML roto o mal codificado sí se cachea (no cambia hasta que cambie el fichero).
- `cmd` se guarda como `str(...)` (un `cmd: 3` ya no llega crudo a `huella.flags_del_cmd`).

### Tests nuevos (`tests/test_topologia.py`)

- `test_yaml_valido_con_forma_rara_no_lanza_y_va_sin_turno` (13 casos parametrizados) y `test_modelo_con_forma_rara_no_lanza` (3): la llamada va envuelta en `try/except` para que un fallo caiga en el assert `leer no devolvio SinTopologia`.
- `test_validar_como_load_go_tampoco_lanza_con_forma_rara`.
- `test_fallo_pasajero_al_abrir_no_se_cachea`: primera llamada con `Path.open` parcheado que lanza `PermissionError`, segunda sin parche y con la misma `mtime` → `Foto`.
- `test_yaml_roto_si_se_cachea`: el contrapeso (el YAML roto no se relee sin cambios).
