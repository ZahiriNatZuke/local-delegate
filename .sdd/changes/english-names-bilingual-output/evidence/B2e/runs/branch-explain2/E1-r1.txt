El código implementa una herramienta de línea de comandos modular para gestionar modelos de IA, demonios y recursos. La función `run` actúa como punto de entrada, inicializando el contexto de idioma con `_argparse_in_language` y ejecutando la lógica tras analizar los argumentos mediante `build_parser`. Este constructor configura los subcomandos principales: `benchmark` (con `test-window` para gestionar ventanas de tiempo mediante `_add_test_window_parser`), `llamaswap` (para residencia de modelos vía `_add_llamaswap_parser`), `serve` (inicia el daemon MCP con `cmd_serve`), `recompute-cost` (recalcula costes con `cmd_recompute_cost` y su alias oculto `cmd_recompute_cost_legacy`), y el bloque de instalación gestionado por `_add_install_parsers`, que incluye `install`, `update` y `uninstall`.

La lógica de instalación y actualización se orquesta en `_run_install`, apoyada por `_install_options` y `_update_options` para procesar argumentos, mientras `_resolve_clients` valida configuraciones y `_warn_deprecated` gestiona comandos obsoletos. Para `llamaswap`, `cmd_init_llamaswap` y `cmd_check_llamaswap` validan presupuestos de VRAM/RAM usando `_check_budget` y `_estimate_all`, mientras `cmd_llamaswap_residency` gestiona cambios atómicos en la configuración mediante `_write_residency` y `_daemon_watch`. Utilidades como `_has_terminal`, `_codex_mcp_set_by_hand` y `_decide_on_foreign_codex` manejan la interacción con el entorno y Codex, mientras `_scaffold_report` y `_print_breakdown` proporcionan salidas detalladas. El sistema también incluye mecanismos de recuperación como `_restore_after_rejection` y validaciones de ruta CLI con `_warn_if_cli_not_on_path`.
