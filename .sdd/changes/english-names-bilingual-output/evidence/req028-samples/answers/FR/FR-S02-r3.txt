## Introducción
Cette topologie recommande de garder le délégué local sur le client pour préserver l'accès aux fichiers locaux.

## 1. Publicar el loopback dentro del tailnet
Le flux utilise Tailscale Serve pour publier les services via HTTPS sur le réseau privé.
**Autenticación de llama-swap** L'authentification utilise des clés API stockées de manière sécurisée dans le Keychain sur Mac ou via des chaînes sécurisées sur Windows, évitant toute exposition dans les fichiers de configuration.

## 2. Mantener el MCP local en la Mac
**Elegir exactamente que revision se prueba** Il est nécessaire de fixer une version spécifique via l'argument `--from` avec un SHA de commit pour tester des changements non publiés sur PyPI.
**Canary automatizado desde la Mac** Un script Python automatise les tests en effectuant des inférences, vérifiant la gestion des chemins locaux et la reconnexion du processus.
**Resultado validado (2026-07-23)** Les tests ont confirmé le succès de vingt inférences et la validation correcte des chemins macOS avec une latence p95 de 2,983 s.

## Alternativa: MCP remoto completo
Cette option publie le service directement depuis le PC, mais elle est moins recommandée car elle utilise les chemins de fichiers Windows.

## Criterio de aceptación
Le service doit répondre via Tailscale, protéger les jetons et valider les fonctions de résumé et de classification.
