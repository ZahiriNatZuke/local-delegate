Ce code définit le point d'entrée principal (`main`) d'un binaire Python, servant de façade unique pour orchestrer deux modes d'exécution distincts : une interface en ligne de commande (CLI) et un serveur MCP (Model Context Protocol). La structure résout un problème d'architecture antérieur où `server.py` et `cli.py` s'importaient mutuellement, créant un cycle dangereux. Ici, la logique de dispatching est déplacée vers ce module, permettant à `server` d'ignorer l'existence du CLI, respectant ainsi la séparation des responsabilités.

Le fonctionnement dépend de la présence d'arguments dans `sys.argv`. Si des arguments sont fournis, le module `cli` est importé de manière différée (pour réduire la latence de démarrage) et sa fonction `run` est exécutée. Sinon, le programme se comporte comme un serveur MCP standard en mode stdio. Avant de lancer le serveur, une fonction utilitaire vérifie si l'entrée standard est un terminal interactif ; si oui, un avertissement est affiché sur `stderr` pour informer l'utilisateur que le programme semble bloqué, car il attend en réalité des messages JSON-RPC.

Le serveur démarre ensuite avec des options configurables, comme l'auto-démarrage du backend ou l'activation d'une interface web de métriques. Une gestion explicite des interruptions (`KeyboardInterrupt`) est implémentée pour intercepter les arrêts manuels (comme Ctrl+C). Cela permet au programme de se terminer silencieusement avec un code de sortie zéro, évitant ainsi l'affichage d'erreurs techniques ou de traces d'exécution qui pourraient être interprétées à tort comme des bugs par les gestionnaires de services.
