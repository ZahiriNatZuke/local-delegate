This Python script automates the preparation of a static website for GitHub Pages by injecting the current project version into specific files. It reads the version string directly from `pyproject.toml` using the standard library’s `tomllib`, ensuring a single source of truth and avoiding manual updates across multiple configuration files.

The core logic involves copying the `site/` directory to a `_site/` destination, excluding files with a `.src.html` suffix which are considered source artifacts rather than published pages. During this process, the script scans all files with extensions `.html`, `.css`, `.js`, `.json`, and `.webmanifest`. If a file contains the placeholder marker `__LD_VERSION__`, it replaces it with the version extracted from `pyproject.toml`. The script explicitly handles line endings by using `newline="\n"` to ensure consistent output across different operating systems, which is crucial for web servers.

The script supports two modes via command-line arguments. By default, it performs the build, printing the paths of modified files. If the `--check` flag is used, it verifies that the destination directory exists and contains no remaining markers. If any files still contain `__LD_VERSION__`, it exits with an error code, indicating a failed or incomplete build. This ensures that the deployed site always reflects the correct version without leaving debug placeholders. The design relies solely on the Python standard library, making it lightweight and suitable for CI/CD workflows without external dependencies.
