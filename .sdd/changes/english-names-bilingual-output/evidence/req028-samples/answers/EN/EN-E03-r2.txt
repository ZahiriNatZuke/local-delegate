This Python script automates the preparation of a static website for GitHub Pages by injecting the current project version into the generated files. It reads the version string directly from `pyproject.toml` using the standard library’s `tomllib`, ensuring a single source of truth and avoiding manual updates across multiple configuration files.

The core logic resides in the `build` function, which copies the `site/` source directory to a `_site/` destination. During this process, it ignores specific source files (marked with `.src.html`) that are not part of the public site. The script then scans all files in the destination directory with extensions like `.html`, `.css`, `.js`, `.json`, and `.webmanifest`. If a file contains the placeholder marker `__LD_VERSION__`, it replaces every occurrence with the version extracted from `pyproject.toml`. The script explicitly handles line endings by using `newline="\n"` to ensure consistent formatting across platforms, particularly preventing Windows-style CRLF line endings in web-served files.

The script supports two modes via command-line arguments. By default, it performs the build, printing the files modified and the version injected. If the `--check` flag is passed, it runs in validation mode. It scans the destination directory for any remaining instances of the marker. If any are found, it exits with a non-zero status code and lists the files that failed substitution, ensuring that no stale placeholders are published. This mechanism guarantees that the version displayed in the site’s UI (such as the hero section or terminal output) always matches the declared project version, maintaining consistency throughout the deployment pipeline without requiring external dependencies.
