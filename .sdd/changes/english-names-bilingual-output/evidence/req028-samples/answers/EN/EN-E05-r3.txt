This Python script prepares Markdown documentation for GitHub Wikis by fixing broken relative links. GitHub Wikis operate in a flat repository structure, meaning relative paths like `../recipes/ollama.md` fail because the directory hierarchy is lost. The script resolves this by converting internal relative links into absolute URLs pointing to the main repository's `blob` view, while leaving external links, anchors, and same-directory links untouched to preserve navigability within the source repo.

The core logic uses a regular expression to identify Markdown links. For each link, it checks if the destination starts with `..`. If so, it resolves the path relative to the source directory, calculates its position relative to the repository root, and constructs a full GitHub URL (e.g., `https://github.com/.../blob/main/path/to/file.md`). Links that do not start with `..` or are external are ignored, as they are already valid in the Wiki context or source context.

The script supports two modes: `--check` to preview changes without writing files, and a default mode that writes the converted Markdown files to a specified destination directory. It processes all `.md` files in the `docs/wiki/` folder, reporting the number of converted links per page and in total. This ensures that the source documentation remains clean with relative links for local reading, while the published Wiki has functional absolute links, preventing 404 errors. The script relies solely on the Python standard library, ensuring it runs without external dependencies in CI/CD workflows.
