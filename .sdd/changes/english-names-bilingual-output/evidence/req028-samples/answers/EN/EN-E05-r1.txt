This Python script prepares Markdown files from a `docs/wiki/` directory for publication as a GitHub Wiki. GitHub Wikis operate in a separate repository where relative links (like `../recipes/ollama.md`) break because the directory structure differs from the main codebase. The script fixes this by converting internal relative links into absolute URLs pointing to the main repository's `blob` view, ensuring they remain functional in the Wiki environment.

The core logic uses a regular expression to find Markdown links `[text](dest)`. For each link, it checks if it is external, an anchor, or a mailto link; if so, it remains unchanged. If the link starts with `..`, indicating it points to a file outside the current Wiki directory, the script resolves the path relative to the project root. It then constructs a full GitHub URL (e.g., `https://github.com/.../blob/main/path/to/file.md`).

The script supports two modes. In default mode, it reads all `.md` files in the source directory, applies the conversion, and writes the updated content to a specified destination directory. It also prints a summary of changes. In `--check` mode, it only reports which links would be converted without writing any files. This ensures that the source documentation remains clean with relative links for local navigation, while the published Wiki gets the necessary absolute links for cross-repository compatibility. The script relies solely on the Python standard library, making it easy to run in CI/CD pipelines without external dependencies.
