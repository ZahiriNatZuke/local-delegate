This code defines the entry point for a binary application, acting as the central hub that coordinates both the Command Line Interface (CLI) and the MCP server. Its primary architectural achievement is resolving a circular import dependency that previously existed between the server and CLI modules. By placing this logic in a separate entry point, the server module no longer needs to import the CLI, thereby eliminating static analysis warnings and adhering to the design principle that the server should remain unaware of the CLI's existence.

The `main()` function implements a dual-mode behavior based on command-line arguments. If arguments are present (`len(sys.argv) > 1`), it lazily imports the `cli` module and delegates execution to `cli.run()`. This deferred import is crucial for performance; it avoids the startup cost of parsing CLI arguments when the application is running as a background MCP server, which typically receives no arguments. If no arguments are provided, the application assumes the role of an MCP stdio server.

Before starting the server, the code checks for interactive terminal usage via `_interactive_terminal_warning()`. If `stdin` is a TTY, it prints a warning to `stderr` to inform the user that the application is waiting for JSON-RPC messages, preventing confusion that might arise from apparent inactivity. The server initialization includes optional features like backend autostart and an embedded metrics web interface, both handled with error suppression to ensure they do not prevent the core MCP server from running. Finally, the code explicitly handles `KeyboardInterrupt` (Ctrl+C) to exit silently with code 0, avoiding noisy traceback outputs that could be mistaken for errors by service managers.
