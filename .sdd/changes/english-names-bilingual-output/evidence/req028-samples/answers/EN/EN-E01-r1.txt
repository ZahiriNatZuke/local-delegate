This Python module validates pricing data for Claude models against a local reference table, ensuring accuracy without network access. It loads `prices.json` and `density.json` from the package resources using `importlib.resources`, caching them for efficiency. The core logic normalizes model IDs by stripping formatting artifacts like `[1m]` and date suffixes, then performs exact lookups to retrieve specific token costs.

The `entry` function retrieves price details for a given model ID, returning `None` if the model is not found, which prevents incorrect price inheritance from similar models. The `_judge` function implements the core validation logic (REQ-013). It calculates the expected cost for a usage row by summing input, cache read, and output token costs, plus web search fees. Crucially, it handles cache creation costs by calculating a range (low to high) based on different cache expiration times (5 minutes vs. 1 hour), as the usage data does not specify the split.

Rows with costs below a minimum threshold (`MIN_JUDGED_COST`) are ignored to avoid rounding errors. If a model is unpriced, it is flagged as "unpriced". Otherwise, the actual cost is compared against the calculated range plus a tolerance margin. If the cost falls within this range, the result is "inside"; otherwise, it is "outside". The `check_rows` function applies this judgment to a list of usage rows, and `verdict` aggregates the results, returning "fail" if any row is "outside" or "unpriced", and "pass" otherwise. This design ensures that pricing discrepancies are detected while allowing for minor calculation variances.
