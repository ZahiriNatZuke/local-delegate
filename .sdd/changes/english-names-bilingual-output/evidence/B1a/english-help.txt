=== local-delegate  --help
usage: local-delegate [-h] [--version]
                      {benchmark,check-llamaswap,init-llamaswap,llamaswap,doctor,serve,recompute-cost,test-window,install,update,uninstall}
                      ...

Installs, diagnoses and serves local-delegate. With no subcommand, this binary starts the stdio
MCP server, which is how Claude Code, Codex and opencode launch it. `check-llamaswap` and `init-
llamaswap` need the [llamaswap] extra.

positional arguments:
  {benchmark,check-llamaswap,init-llamaswap,llamaswap,doctor,serve,recompute-cost,test-window,install,update,uninstall}
    benchmark           Ejecuta el corpus v2 de tareas reales contra un backend canary y escribe
                        JSONL.
    check-llamaswap     Checks the VRAM (and optionally RAM) budget of the groups in a
                        config.yaml.
    init-llamaswap      Generates/updates the groups of a llama-swap config.yaml with a VRAM/RAM
                        guardrail.
    llamaswap           Residency and TTL of the llama-swap models (needs the [llamaswap] extra).
    doctor              Diagnoses the scaffolding (hooks, skill, memory, MCP), the daemon and the
                        backend.
    serve               Serves Streamable HTTP MCP (/mcp) and the dashboard (/) as a singleton
                        daemon.
    recompute-cost      Reads the Claude Code transcripts and leaves in the log directory the
                        attribution backfill, the N aggregates, the price check and the quota
                        points.
    test-window         Marks test windows: the usage log rows that fall inside do not count in
                        the panel, in local_status or in the cost.
    install             Installs hooks, skill, memory and the MCP entry in Claude Code / Codex /
                        opencode.
    update              Updates the pin, completes whatever the scaffolding is missing and leaves
                        the daemon up.
    uninstall           Undoes what `local-delegate install` installed (only its own).

options:
  -h, --help            show this help message and exit
  --version             prints the installed version and exits

=== local-delegate install --help
usage: local-delegate install [-h] [--clients {auto,claude,codex,opencode}]
                              [--target {claude,codex,opencode,all}] [--home HOME] [--dry-run]
                              [--python PYTHON] [--no-hooks] [--no-skill] [--no-memory] [--no-mcp]
                              [--agents] [--no-client-cli] [--enable-read-hook]
                              [--mcp-mode {stdio,http}] [--base-url BASE_URL] [--api-key-env]
                              [--web-token-env | --no-web-token-env] [--pin-version PIN_VERSION]
                              [--force-mcp-codex]

Installs the whole integration in the user's HOME: advisory hooks, the local-delegation skill, a
managed block in CLAUDE.md/AGENTS.md and the MCP server entry. It is idempotent (blocks with
markers, .bak backups) and is undone with `local-delegate uninstall`.

options:
  -h, --help            show this help message and exit
  --clients {auto,claude,codex,opencode}
                        client to configure (repeatable; default: auto = the installed ones)
  --target {claude,codex,opencode,all}
                        legacy, same as --clients; `all` forces the three even if they are not
                        installed
  --home HOME           alternative HOME (for tests)
  --dry-run             describes the changes without writing
  --python PYTHON       interpreter that runs the hooks (default: python3 / python on Windows)
  --no-hooks            does not install the advisory hooks
  --no-skill            does not install the local-delegation skill
  --no-memory           does not touch the global CLAUDE.md / AGENTS.md
  --no-mcp              does not register the MCP server in the client config
  --agents              updates the ~/.claude/agents that already declare local_* tools (opt-in)
  --no-client-cli       does not use the `claude` binary; edits ~/.claude.json directly
  --enable-read-hook    registers and TURNS ON the experimental PreToolUse/Read hook (off by
                        default)
  --mcp-mode {stdio,http}
                        stdio (uvx, default) or http (shared daemon at /mcp)
  --base-url BASE_URL   LOCAL_DELEGATE_BASE_URL of the MCP entry (e.g. the remote backend of
                        another machine)
  --api-key-env         forwards LOCAL_DELEGATE_API_KEY from the environment (never writes the
                        credential)
  --web-token-env       with --mcp-mode http, authenticates against the daemon by referencing
                        LOCAL_DELEGATE_WEB_TOKEN from the environment (never writes the
                        credential). Without this flag or --no-web-token-env, the entry keeps the
                        header it already had
  --no-web-token-env    removes the authorization header from the MCP entry even if it had one
  --pin-version PIN_VERSION
                        pins the package version in the MCP entry (e.g. 0.11.0)
  --force-mcp-codex     replaces a hand-written Codex entry without asking (leaves a .bak)
=== local-delegate update --help
usage: local-delegate update [-h] [--dry-run] [--home HOME] [--version VERSION]
                             [--restart-backend] [--no-restart]

Checks the real state of the machine with the same checks as `doctor`, updates the version pin
wherever there is one, completes the missing configuration and ends by leaving the daemon up: it
restarts it if it was running and starts it if not. The inference backend is not touched unless
asked with --restart-backend.

options:
  -h, --help         show this help message and exit
  --dry-run          describes the changes without writing
  --home HOME        alternative HOME (for tests)
  --version VERSION  version to pin (default: the latest one published on PyPI)
  --restart-backend  also restarts llama-swap (NOT touched by default: it unloads the models from
                     VRAM)
  --no-restart       does not touch the daemon; only repairs and reports

  --ram-margin-gb RAM_MARGIN_GB
                        RAM margin reserved for the OS/other apps (default 2.0, only with --ram-

=== local-delegate llamaswap residency --help
usage: local-delegate llamaswap residency [-h] [--config CONFIG]
                                          [--none | --pin MODEL | --restore BAK]
                                          [--ttl MODEL=SECONDS] [--group GROUP]
                                          [--vram-gb VRAM_GB] [--reserve-gb RESERVE_GB]
                                          [--vram-model ID=GiB] [--dry-run] [--now]

With no options, shows the residency of the llama-swap config: each model with its group, the
effective TTL and the verdict ("no resident (recommended)" or "resident: X"). Never prints keys or
`cmd`.

Effective TTL: in llama-swap (load.go) a missing `ttl` or -1 means `globalTTL`, which defaults to 0.
So WITHOUT `globalTTL` OR `ttl`, EVERY MODEL HAS AN EFFECTIVE TTL OF 0: none is ever unloaded by
TTL and all of them show up as resident. To leave them with no resident, `--none` then asks for
`--ttl` for all of them.

The config comes from --config; otherwise from LLAMASWAP_CONFIG; otherwise from the one the daemon
uses. If none of those answers, "unknown" and no file is opened.

Writing makes llama-swap (with -watch-config) reload in about 2 s, UNLOAD EVERY MODEL and CUT THE
REQUESTS IN PROGRESS (from any client). That is why nothing is written while local-delegate
delegations are in progress, requests are in flight in llama-swap or models are loaded, nor when
that cannot be known (no daemon and no llama-swap credential in the shell): --now writes anyway.

Before writing, it leaves a <config>.<YYYYMMDD-HHMMSS>.bak copy and replaces the file atomically.
Afterwards it says what llama-swap did: reloaded; rejected (and the copy is restored, so the file
matches what is running); not watching the file (it will apply on the next start); or down.

options:
  -h, --help            show this help message and exit
  --config CONFIG       llama-swap config.yaml
  --none                leaves the config with no resident: moves the persistent groups to the
                        swap group and gives --ttl to the models with an effective TTL of 0
  --pin MODEL           OPT-IN residency: the model moves to a persistent group (swap and
                        exclusive false) with ttl 0 and holds VRAM permanently; refused if it does
                        not fit
  --restore BAK         goes back to a .bak copy, byte for byte
  --ttl MODEL=SECONDS   changes the TTL (integer >= 1; 0 is --pin; -1 only with globalTTL > 0);
                        repeatable
  --group GROUP         target group for --none
  --vram-gb VRAM_GB     GPU VRAM in GiB (--pin)
  --reserve-gb RESERVE_GB
                        VRAM left for the rest of the PC (default 2)
  --vram-model ID=GiB   measured VRAM of a model (repeatable); without it, --pin is refused
  --dry-run             prints only the lines that would change
  --now                 writes even if it cannot be known whether delegations are in progress
